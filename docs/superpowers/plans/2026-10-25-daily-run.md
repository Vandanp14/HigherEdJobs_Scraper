# Daily One-Command Run Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `./daily.sh` wipes jobs, serves API + dashboard on one port, opens it, and runs HigherEdJobs + AIR. The scraper dedupes across groups and pauses for human verification.

**Architecture:** A shell script orchestrates the existing FastAPI app, which already mounts `frontend/dist`. Database gains `clear_jobs`, `upsert_job` (returns id), `add_match`, and a one-time `it` group disable. A new `backend/app/access.py` holds the verification wait loop. The dashboard polls while a run started elsewhere is in progress.

**Tech Stack:** Python 3 / FastAPI / Playwright async / SQLite; React + Vite; bash.

**Spec:** `docs/superpowers/specs/2026-10-25-daily-run-design.md`

## Global Constraints

- Do not lower `HEJ_REQUEST_DELAY` and do not parallelize HigherEdJobs detail pages.
- Never delete `data/browser-state.json`.
- Python: four-space indent, `snake_case`. TS: two-space, `camelCase`.
- Tests: `.venv/bin/pytest`; new tests named `test_*.py` in `backend/tests/`.

## Review Focus

- First run with no `data/jobs.sqlite3`: script must not fail on the wipe. Test: `test_clear_jobs_on_fresh_database` (Task 1).
- Wipe leaves orphan `job_search_matches` / `sponsorship_analysis` rows. `manage-data.py` connects without `PRAGMA foreign_keys`, so cascades never fire and reused job ids inherit stale evidence. Test: `test_clear_jobs_removes_matches_and_analysis` (Task 1).
- User re-enables `it` group, then restarts: it must stay enabled. Test: `test_it_group_disable_runs_once` (Task 1).
- Port 8000 already in use (an old dev server): script must say so and exit, not open a dashboard backed by stale code. Covered in the Task 4 manual check.
- Verification never solved: the run must still finish and record the error, not hang forever. Test: `test_wait_for_access_times_out` (Task 2).

### Task 1: Database — clear, id-returning upsert, add_match, `it` disable

**Files:**
- Modify: `backend/app/database.py` (`migrate`, `upsert`; new methods)
- Modify: `scripts/manage-data.py` (`clear-jobs` uses `Database.clear_jobs`; tolerate missing DB for `clear-jobs`)
- Test: `backend/tests/test_daily_database.py`

**Interfaces:**
- Produces:
  - `Database.clear_jobs() -> None`: deletes all rows from `sponsorship_analysis`, `job_search_matches`, `jobs`, and `scrape_runs`, in that order. It does not touch `search_groups`, then commits.
  - `Database.upsert_job(draft: JobDraft, group_id: str | None = None) -> tuple[int, bool]`: (job_id, is_new). Current `upsert` body moves here, and `upsert` returns `self.upsert_job(...)[1]`.
  - `Database.add_match(job_id: int, group_id: str) -> None`: same SQL as the match insert in `upsert`, then commits.
  - Migration: if `PRAGMA user_version` < 1, run `UPDATE search_groups SET enabled=0 WHERE id='it'`, then `PRAGMA user_version=1`.

### Task 2: Verification wait loop

**Files:**
- Create: `backend/app/access.py`
- Modify: `backend/app/config.py` (add `state_path: Path = ROOT / "data/browser-state.json"`, `verification_timeout_s: float = float(os.getenv("HEJ_VERIFICATION_TIMEOUT", "300"))`)
- Test: `backend/tests/test_access.py`

**Interfaces:**
- Produces: `async def wait_for_access(page, *, timeout_s: float, poll_s: float = 3.0, alert: Callable[[], None], save_state: Callable[[], Awaitable[None]]) -> None`.
  - Calls `checked_soup(await page.content())`. If it passes, return immediately with no alert.
  - On `AccessBlocked`: call `alert()` once, then poll every `poll_s` until `checked_soup` passes, then `await save_state()` and return.
  - Re-raise the last `AccessBlocked` after `timeout_s`.
- Produces: `def alert_user() -> None`. Prints `"\a⚠ HigherEdJobs needs verification — solve it in the open browser window. The run will continue automatically."` to stderr, then calls `subprocess.Popen(["afplay", "/System/Library/Sounds/Glass.aiff"])`. Swallow `OSError`.

### Task 4: `daily.sh`, dashboard polling, README

**Files:**
- Create: `daily.sh` (executable)
- Modify: `frontend/src/main.tsx` (poll for externally started runs; update the access-blocked notice text)

**`daily.sh` behavior, in order:**
1. `set -euo pipefail` and `cd "$(dirname "$0")"`.
2. If `lsof -iTCP:8000 -sTCP:LISTEN` finds a listener, print "Port 8000 in use — stop the other server first." and exit 1.
3. Wipe with `.venv/bin/python scripts/manage-data.py clear-jobs`.
4. If `frontend/dist/index.html` is missing, or any file under `frontend/src` is newer (`find frontend/src -newer frontend/dist/index.html | grep -q .`), run `(cd frontend && npm run build)`.
5. Start `.venv/bin/uvicorn backend.app.main:app --host 127.0.0.1 --port 8000` in the background. `trap 'kill $SERVER 2>/dev/null' EXIT INT TERM`.
6. Poll `curl -sf http://127.0.0.1:8000/api/health` every 0.5s for up to 30s. Fail with a message on timeout.
7. Open `http://127.0.0.1:8000`.
8. Fire `curl -s -X POST .../api/runs/air >/dev/null &` and `curl -s -X POST -H 'content-type: application/json' -d '{}' .../api/runs >/dev/null &`.
9. Print "Dashboard: http://127.0.0.1:8000 — jobs appear as they're fetched. Ctrl+C to stop." Then `wait $SERVER`.

**Dashboard:** add a `useEffect` with a 10s interval.
- Each tick: if `activeRun` is null, `request('/sources')`, then `setSources`.
- If any `last_run` has `completed_at === null`, call `load()` and set the notice to "A run started by daily.sh is in progress — new jobs appear automatically."
- When a run that was in progress shows completed on a later tick, call `load()` once and clear that notice.
